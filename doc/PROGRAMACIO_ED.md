# 🖥️ PROGRAMACIÓ I ENTORNS DE DESENVOLUPAMENT
## 1. 📊 Organització del projecte a Taiga

Per al projecte s’ha fet ús de Taiga per a la gestió de tasques i sprints.

Es va crear un *backlog* durant el Sprint 0, en el qual es van afegir totes les *user stories* que es consideraven necessàries. Posteriorment, durant el desenvolupament del projecte, se’n van incorporar algunes de noves.

Les tasques es van repartir entre els diferents sprints segons les hores disponibles i la puntuació (story points) de cada tasca. En alguns sprints es van poder completar tasques addicionals, mentre que en altres casos va ser necessari reassignar algunes tasques al sprint següent.

Les tasques es van assignar a cada membre de l’equip, i cadascú era responsable de moure-les segons el seu estat (pendent, en progrés o finalitzada).

---

## 2. 🧩 Tipus de tasques creades

Es van crear tasques en format *user stories*, on es definia què necessitava l’usuari o el sistema. Es van diferenciar tasques d’usuari, d’administrador i de tècnic segons els requisits del projecte.

Cada *user story* es desglossava en diverses subtasques que permetien completar els requisits definits.

### User stories implementades en el projecte:

- Veure estat de la incidència (usuari)
- Landing page
- Registrar incidència
- Connexió amb la base de dades (storyless tasks)
- Registrar actuació (rol tècnic)
- Crear pàgina per afegir una actuació a una incidència
- Crear pàgina accessible per ID d’incidència
- Tancar incidència
- Crear pàgina de gestió d’incidències per ID, amb visualització en mode lectura
- Implementar funcionalitat per marcar incidències com a tancades (amb data)
- Llistar incidències
- Llistar totes les incidències ordenades i amb codificació de colors
- Modificar incidències i assignar prioritat (rol root)
- Filtres per ordenar per prioritat, estat, etc. amb JavaScript
- Filtrar per assignació i estat
- Detecció d’errors previs a l’enviament del formulari
- Missatges d’error si l’actualització d’administrador s’envia incompleta
- Validacions JavaScript a la pàgina d’afegir actuació (mínim 20 caràcters a la descripció)
- Validacions JavaScript a la pàgina d’afegir incidència (camps obligatoris)
- Generació d’informes d’incidències
- Pàgina d’Informe de tècnics
- Registre de logs del sistema
- Pàgina de Consum per departaments
- Creació de capçaleres, peus de pàgina i includes reutilitzables
- Millores generals per fer l’aplicació més usable i agradable

---

## 3. 📅 Planificació (sprints)

El projecte s’ha dividit en diferents fases: Sprint 1, Sprint 2 i Sprint 3.

En el primer sprint es van desenvolupar principalment les funcionalitats d’usuari. En el segon sprint es van implementar les funcionalitats de tècnic i administrador. L’últim sprint es va dedicar a completar tasques pendents i a realitzar millores generals.

Cada matí es feia una breu reunió per comentar el treball realitzat, les tasques en curs i les tasques previstes.

Els divendres es planificaven les tasques del sprint següent i es distribuïen de manera equitativa. Durant el desenvolupament, el planning es va anar adaptant segons les necessitats del projecte.
